# MetalVoice2 v2.0 proposal · local RVC voice conversion

Add a **Voice Changer** tab beside **Microphone**. Keep one capture device, input channel, virtual output, Start/Stop, Mute and latency display for the whole app. Changing tabs only navigates. A separate **Voice conversion** switch enables the selected voice. With it off, v1 cleanup and routing run at their existing latency and the conversion worker sleeps. The first milestone is to reproduce one familiar voice offline before choosing a shorter live processing interval.

## What to reproduce

The reference is the **RVC** slot “MiaGirlfriendAudio” in VCClient 2.0.78-beta for Mac. The other visible slot is Beatrice and uses a different engine. The screenshot shows unity input/output gain, +10 semitones, index 0.50, RMVPE ONNX, 500 ms Chunk, 340 ms Extra, a 50 ms crossfade, a −120 dB gate, and CPU selected. Echo is off and both suppressors are on. The advanced screenshot has filters enabled at 100 Hz and 10 kHz. Save this as a comparison preset. Verify which checkpoint, index and speaker were actually active. An index slider at 0.50 alone cannot establish that a matching index was loaded. For conversion comparisons, explicitly enable conversion in both apps. The earlier passthrough listening test established a cleanup preference only.

I traced the RVC dispatch in public commit 7e2ce5c. Its manager selects RVCr2 and VoiceChangerV2. The 2.0.78 release notes confirm changes to RVC upload and available chunk sizes. The screenshots establish the selected UI values. Exact filter placement, index search settings and advanced control behavior in that Mac binary still need reference recordings or inspection of the matching build. ## Controls and priorities

| Feature | Proposed behavior |
|---|---|
| Model library | Import an exported RVC inference checkpoint (.pth) and optional companion FAISS .index. List voices by name, show import progress, Ready or a specific compatibility error. Allow attaching/replacing an index later, removing a voice and restoring per-model settings. Show speaker selection only for multispeaker checkpoints. |
| Input and output gain | Show dB, unity at 0 dB (VCClient 1×). Put conversion input trim after the v1 cleanup stages and before gate/feature extraction. Put output trim after synthesis and stitching. Ramp live changes and show clipping on the existing meters. |
| Pitch | Integer semitones, 0 neutral. Start with ±24. +10 multiplies voiced F0 by about 1.78. Store the offset per voice. Disable pitch and F0 controls when a checkpoint was trained without F0. |
| Index | A 0–100% blend between input content features and nearest target-training features. 50% blends features equally. It affects timbre and sometimes diction. At zero, skip search entirely. Disable the control until a populated, dimension-compatible index is paired. Let the user confirm the pairing because feature width alone cannot identify the right voice. |
| Timing | Expose Chunk and Extra independently in milliseconds. Offer the screenshot preset plus measured conversation/quality presets after benchmarking. Keep the exact values editable in Advanced. Display measured processing p99 beside the chunk deadline. |
| F0 estimator | RMVPE first for pitch-guided voices. It estimates the fundamental frequency and voiced/unvoiced regions. ONNX is the execution format. Retain the reference estimator's preprocessing and decoding when comparing a Core ML implementation. Benchmark WORLD Harvest plus StoneMask as a CPU alternative for voices on which RMVPE misses pitch or jumps an octave. Defer more extractors until listening tests identify a benefit. |
| Voice cutoff / N. Gate | A separate level threshold in dBFS, off by default. −120 dB is effectively open for a typical mic. Add a soft opening/closing ramp, hysteresis and a short hold. Test quiet consonants and the first word after silence before enabling any compute-saving skip. |
| High-pass and low-pass | A two-handle frequency range in Hz can control both filters, with independent bypass. High-pass attenuates low rumble, low-pass attenuates upper frequencies and can dull “s” sounds. Keep the level gate separate because it acts on amplitude. Test 100 Hz / 10 kHz for reference and both filters off. Verify upstream placement by comparing low/high test signals with conversion on and off. A 10 kHz cutoff solely before a 16 kHz analysis stream cannot shape 10 kHz in the synthesized output. |
| Crossfade | Implement automatic waveform alignment and overlap blending from the first prototype. Start by testing the screenshot's 50 ms overlap, then shorter overlaps at short chunks. An advanced override is useful for clicks or doubled consonants. |
| Other useful controls | Save gain, pitch, index, timing and speaker per model. Test unvoiced-consonant protection at high index strengths and +10 pitch. Verify against a genuine pre-retrieval feature copy before exposing the option. For experimental volume tuning, compare reference output-level following with fixed gain on loud/quiet speech. The public path scales with the square root of input RMS. Check the binary before claiming exact “sqrt” parity. |

The public pipeline does one-nearest-neighbor retrieval on its active path, even though it also contains an eight-neighbor branch. Matching the actual reference search matters more than adding extra knobs. The public Protect path takes its saved feature copy after retrieval, so its intended effect needs an independent listening and signal test. Keep performance monitoring in **Details**. The output-buffer ratio, clear-buffer command and server truncation setting concern queue management. Implement bounded queues, report actual depth/drops, and flush stale frames on device or model changes. Leave REST, Socket.IO broadcast, passthrough confirmation, server controls, analyzer, recording and monitor gain out of this tab. Merge Lab combines compatible model weights to create another voice. ONNX export serializes a model graph for another runtime. Neither needs a user-facing control to run an imported voice. ## Where the delay comes from

**Chunk** sets how much fresh audio triggers one conversion. At 48 kHz, 24,000 new samples take 500 ms to arrive. The screenshot's 0.30 s “convert” reading is a separate processing measurement. If representative, 300 ms work per 500 ms of audio uses 60% of the deadline. It says little about worst-case stalls or the cost at a different window size.

**Extra** supplies previously captured audio on the left of the inference window. RVCr2 resamples to 16 kHz, appends each block to rolling history, includes Chunk + Extra + crossfade + alignment search, rounds to the feature hop, pads missing history at startup, then crops historical output. The stitching code searches for a matching waveform position and blends the join. Extra can stabilize pronunciation or pitch at chunk boundaries, and repeatedly analyzing it costs time. The latency display should use timestamps for emitted samples and include real buffering, lookahead, inference and scheduling without double counting. [Chunk accumulation](https://github.com/w-okada/voice-changer/blob/7e2ce5c4800010bbc7604968bd29b802534fac05/client/lib/src/client/VoiceChangerWorkletNode.ts#L282-L303) · [Rolling window, gate and crop](https://github.com/w-okada/voice-changer/blob/7e2ce5c4800010bbc7604968bd29b802534fac05/server/voice_changer/RVC/RVCr2.py#L119-L250) · [SOLA alignment](https://github.com/w-okada/voice-changer/blob/7e2ce5c4800010bbc7604968bd29b802534fac05/server/voice_changer/VoiceChangerV2.py#L230-L282)

| Chunk / Extra | What the M1 Max experiment answers |
|---|---|
| 500 / 340 ms | Match the screenshot's sound and establish cost with the actual voice. |
| 500 / 80 ms | Same output cadence. Does extra history audibly improve this voice? |
| 350 / 340 ms | Same history as the screenshot. Does a 150 ms shorter chunk preserve the sound and meet its tighter deadline? Also compare 350 / 80 to separate the two effects. |
| 200, 120, 80, then 50 ms / best tested history | Find the shortest reliable setting. Repeat with shorter histories and overlaps. Stop lowering the chunk when speech degrades, misses accumulate, or energy cost exceeds the chosen budget. |

For example, ignoring overlap, search and padding, 500/80 examines roughly 580 ms twice per second while 350/340 examines 690 ms about 2.86 times per second. A full-window implementation would process about 70% more input duration per second in the latter configuration. This illustrates repeated work, not a CPU or sound-quality prediction.

## Native implementation sequence

1. **Reference first.** Obtain one user-supplied RVC .pth and its optional index. Identify version, expected content encoder/layer, F0 flag, speaker count, model output rate and index type. Render a fixed speech clip with conversion enabled in VCClient and in an offline reference runner. Use dry input first, then v1 cleanup and the user's usual VCClient suppression to distinguish conversion differences from preprocessing. Keep reference clips local. Establish successful playback and pronunciation before optimizing.
2. **Import once.** Support standard RVC v1/v2 inference exports incrementally, starting with the user's actual variant. Standard v1/v2 feature widths are 256/768. Enumerate supported decoder configurations and rates (test 32/40/48 kHz), then add non-F0 and multispeaker fixtures before advertising support. A training checkpoint, custom embedder or arbitrary .pth should give an actionable error. Use an isolated, resource-limited importer with restricted tensor loading, shape/size limits and validated index parsing. Build the known architecture locally. Cache the prepared graph, validated index, encoder identity and preprocessing parameters by content hash and converter/runtime version. Publish the cache atomically. Reopening a prepared voice should need neither network access nor a Python process. Verify distribution terms for shared encoder/F0 weights independently of the user's checkpoint. [Checkpoint interpretation](https://github.com/w-okada/voice-changer/blob/7e2ce5c4800010bbc7604968bd29b802534fac05/server/voice_changer/RVC/RVCModelSlotGenerator.py) · [PyTorch serialization](https://docs.pytorch.org/docs/stable/notes/serialization.html) · [FAISS index I/O](https://github.com/facebookresearch/faiss/wiki/Index-IO,-cloning-and-hyper-parameter-tuning)
3. **Build a native offline runner.** Resample cleaned mono audio to 16 kHz with persistent resampler state. Run the checkpoint-compatible HuBERT/ContentVec encoder and RMVPE, apply semitone shift and optional retrieval, then run the target decoder and return its output to the device rate. Compare intermediate F0, content features, retrieved neighbors, voiced/unvoiced decisions and aligned audio against the reference. Use fixed excitation/seed where supported for repeatability. Prototype direct Core ML export of each supported network using known architectures; use ONNX Runtime CPU as a parity/performance fallback where export or operator coverage fails. Package and measure any fallback before promising broad import support.
4. **Connect to v1 transport.** Feed a dedicated conversion worker from the existing cleanup path using bounded, timestamped queues. Give clean pass-through its current fast path. Keep inference, index search, compilation, memory allocation and file I/O off Core Audio callbacks. Prewarm the next model off the live path, switch at a block boundary, and reset history on gaps. Mute must clear queued speech immediately. On overload, flush stale converted speech, fade to silence and report the missed deadline. Exposing the original voice during a conversion failure should require explicit user choice. [Existing audio worker](../Sources/AudioCore/AudioCore.cpp) · [Transport](../Sources/AudioCore/Transport.cpp) · [Panel](../Sources/MetalVoice2/MenuView.swift)
5. **Optimize the measured bottleneck.** Profile encoder, F0, retrieval, generator, resampling, stitching and queue wait separately. Benchmark Core ML CPU, CPU/GPU and automatic placement on M1 Max with the same inputs and v1 suppressors both off and on. Compare CPU/Accelerate retrieval against alternatives including transfer cost. Preallocate rings and scratch space, skip unused stages and precompile a small set of window shapes. Bidirectional encoders and pitch estimators can change previous frames when new context arrives. Cache only features proven equivalent across overlapping windows, or quantify the quality cost of an approximation. Compare FP16 with FP32 on quiet and high-pitched speech. [Core ML flexible input shapes](https://apple.github.io/coremltools/docs-guides/source/flexible-inputs.html)
6. **Qualify presets and ship the tab.** Run the timing grid with sustained vowels, fast speech, breaths, quiet word endings, sibilants, pitch glides and transitions out of silence. Blind, loudness-matched comparisons should score target-voice resemblance, intelligibility, naturalness and seam artifacts separately. Supplement listening with transcript error, pitch error/octave jumps and target-speaker similarity where suitable reference audio exists. PESQ/STOI against the original speaker would penalize the intended transformation. Compare to the converted reference instead of using v1 denoiser scores to rank voices.

**Proposed release gates on M1 Max.** First reproduce the reference sound at 500/340. For a conversation preset, aim for a 120 ms or shorter chunk, total measured capture-to-virtual-output p95 below 250 ms, conversion p99 below 80% of its chunk deadline, and zero underruns or growing backlog in a 30-minute run. Repeat under a normal call workload and with the intended cleanup model. Report p50/p95 path delay, p99/max compute, misses, startup, peak memory and energy per minute. Validate reported delay using aligned speech onsets or a voiced test pattern captured from the virtual output. Recheck the v1 bypass against its existing latency and CPU baseline. These are targets; publish the fastest preset that actually passes quality and stability tests, even if the first release needs a longer chunk.
